# Web / Capacitor note editor — speaker-section behavior spec

Research baseline for a native parity rewrite of speaker sections.

**Source of truth:** the web editor that shipped in Capacitor before Phase 7
removed the site WebView from iOS (`b0ec5ab` / PR #44) and before the native
editor landed (`c77c197` / PR #46).

**Version compared:** `c77c197^` vs `HEAD` for
`src/components/notebook-doc.tsx`, `src/lib/notebook-html.ts`,
`src/components/notebook-editor.tsx`, and speaker CSS in `src/styles.css` —
**byte-identical (empty diff).** Documenting current tree lines is therefore
documenting the pre–Phase 7 web editor.

**Not TipTap / ProseMirror.** Grep of the repo finds no TipTap/ProseMirror
usage. The live editor is a single `contenteditable` root with custom line /
speaker DOM conventions.

---

## 1. Architecture

### 1.1 Contenteditable document root (not per-line editors)

`NotebookDoc` renders one `contentEditable` host:

```550:557:src/components/notebook-doc.tsx
    <div
      ref={ref}
      contentEditable={!readOnly}
      suppressContentEditableWarning
      role="textbox"
      aria-multiline="true"
      className="note-doc outline-none"
```

React does **not** mount a component tree of lines. State is a `NoteBlock[]`
tree; HTML is generated by `blocksToHtml` and written into `innerHTML` when a
signature changes (`notebook-doc.tsx:195-213`). User edits are periodically
parsed back with `htmlToBlocks` (`notebook-doc.tsx:362-391`).

### 1.2 Model vs DOM

| Layer | Shape |
| --- | --- |
| Legacy / web store | `NoteBlock` = `LineBlock` \| `SpeakerBlock` (`src/lib/notebook.ts:13-28`) |
| DOM | Top-level `.note-line` divs **or** `<section class="note-speaker" data-speaker-block>` wrapping a non-editable head + child `.note-line`s |
| Native wire (Phase 7+) | `NoteDocumentV1` with `speakerSection` (`src/lib/native/api/note-document.ts:98-105`) |

`NotebookLine` (`src/components/notebook-line.tsx`) is a **legacy per-line
contenteditable** component. The current editor path does **not** mount it;
`NotebookDoc` only imports helpers (`placeCaret`, `isLineHtmlEmpty`,
`consumeTrigger`) from that file (`notebook-doc.tsx:16`).

### 1.3 Line identity

Each editable paragraph is:

```html
<div class="note-line" data-line-id="…" data-kind="p|h|ul|ol">…</div>
```

Built in `lineToHtml` (`notebook-html.ts:174-177`) and at runtime via
`makeLine` (`notebook-doc.tsx:465-471`).

### 1.4 Structural insight (header)

**The speaker header is a `contenteditable="false"` block inside the editable
root.** It is not text in the document flow that the user can type into. Name,
chevron, preview, and × live in `.note-speaker-head` and are excluded from
inline parsing. Body text lives only in descendant `.note-line` nodes.

## 2. How a speaker section is inserted

### 2.1 Entry points

| Entry | Path |
| --- | --- |
| Toolbar `UserRound` | `notebook-editor.tsx:513-526` → `setPeople(true)` → `NotebookSpeakerSheet` → `onPick` → `addSpeaker` |
| Trailing / more menu “Speakers” | `notebook-editor.tsx:560-573`, `865-868` → same sheet |
| Typing `@` as a trigger | `consumeTrigger` (`notebook-line.tsx:225-236`) → `onTrigger("at")` (`notebook-doc.tsx:382-388`, `notebook-editor.tsx:664-667`) → opens speaker sheet |

Whole-note speaker (chip under title) is a **different** concept
(`note.speakerId`); picking with `pickNoteSpeaker` sets that chip and does
**not** insert a section (`notebook-editor.tsx:844-849`).

### 2.2 First-attribution ask (whole note vs section)

`addSpeaker` (`notebook-editor.tsx:328-336`):

1. If `noteNeedsSpeakerAsk(latest())` — no `note.speakerId` and no section
   speakers yet (`notebook.ts:147-151`) — show ActionSheet
   (`notebook-editor.tsx:872-895`).
2. “Whole note” → `patch({ speakerId })` only.
3. “Section” → `insertSpeakerSection(speaker)`.
4. Otherwise (already attributed) → `insertSpeakerSection` directly.

### 2.3 `insertSpeakerSection` block shape and placement

```302:326:src/components/notebook-editor.tsx
  function insertSpeakerSection(speaker: Speaker) {
    upsertLocalSpeaker(speaker);
    const child = emptyLine();
    const block: SpeakerBlock = {
      id: newNoteId(),
      type: "speaker",
      speakerId: speaker.id,
      title: "",
      children: [child],
    };
    updateBlocks((blocks) => {
      // Empty / bare notes: replace the blank starter line so the section
      // speaker head is visible immediately (no invisible empty paragraph above).
      const current = { ...latest(), blocks };
      if (noteIsBare(current)) {
        return [block, emptyLine()];
      }
      const withSpeaker = insertAfterAnchor(blocks, focusId, block);
      const last = withSpeaker[withSpeaker.length - 1];
      if (last?.id === block.id) return [...withSpeaker, emptyLine()];
      return withSpeaker;
    });
    setFocusId(child.id);
    setActive(speaker.id);
  }
```

Rules:

1. New section always has **one empty child line** and `title: ""`.
2. **Bare note** (`noteIsBare`: no whole-note speaker, no sections, all lines
   empty — `notebook.ts:170-174`): replace body with `[speakerSection, emptyLine]`.
   Ensures the head is not preceded by an invisible empty paragraph.
3. Otherwise: `insertAfterAnchor(blocks, focusId, block)`
   (`notebook-editor.tsx:32-52`):
   - If focus is on a top-level line → insert section **after that line**.
   - If focus is **inside** a speaker (focus line is a child) → insert the new
     section **after the entire parent speaker block** (not nested).
   - If `focusId` is null → append.
4. If the new section ends up **last** in the array, append another
   `emptyLine()` after it so there is always a tap target below.
5. Sets React `focusId` to the new child and `notebookActiveSpeakerId` to the
   speaker (shows toolbar exit `X`).

### 2.4 Caret after insert — important gap

`setFocusId(child.id)` updates React state only. `NotebookDoc` is **not** given
`focusId` as a prop and has **no** effect that focuses
`[data-line-id="${child.id}"]` after insert.

When blocks change, `NotebookDoc` rewrites `innerHTML` and, if still focused,
restores the caret to the **pre-rewrite selection line** if that id still
exists (`notebook-doc.tsx:199-212`). Consequences:

- Non-bare insert after the current line: caret typically **stays on the line
  above** the new section; React `focusId` / active speaker still point at the
  new child.
- Bare insert: old line id is gone; caret is **not** explicitly placed into the
  new child.

Native parity should treat intentional “focus first body line of new section”
as a product decision: the React `focusId` intent exists, but the web DOM caret
path does not reliably honor it.

### 2.5 Toolbar “exit speaker”

`exitSpeaker` (`notebook-editor.tsx:259-272`) uses `ensureLineAfter`
(`notebook-editor.tsx:119-128`): ensure a non-speaker line exists immediately
after the active section; focus that line id; clear active speaker. Again, no
direct `placeCaret` call into the doc.

| Element | Role |
| --- | --- |
| `<section class="note-speaker">` | Block wrapper; `data-speaker-block` = block id; `data-speaker-id` = catalog speaker; `data-collapsed`; **inline `border-color` = speaker color** |
| `.note-speaker-head` | **`contenteditable="false"`**; whole head is toggle hit target via `data-toggle-speaker` |

| `.note-speaker-name` | Escaped speaker name, or `"—"` if missing from `speakers[]` |
| `.note-speaker-preview` | First non-empty **plain text** of children (refs contribute `""` in preview build — `notebook-html.ts:196-203`); shown only when collapsed via CSS |
| `.note-speaker-remove` | × button; `data-remove-speaker` = **block id** (not `speakerId`) |

### 3.2 Avatar / icon

**There is no avatar image or color-dot inside the section header.** Speaker
color is expressed only as the section’s left border
(`style="border-color:…"` + CSS `border-left: 2px solid` —
`styles.css:408-412`).

A color **dot** appears on the **whole-note** chip under the title
(`notebook-editor.tsx:625-628`), which is outside the contenteditable document.

### 3.3 Non-editable confirmation

1. Head markup sets `contenteditable="false"` (`notebook-html.ts:205`).
2. CSS: `.note-speaker-head` and `.note-speaker-remove` use `user-select: none`
   (`styles.css:414-422`, `475-488`).
3. `htmlToBlocks` skips stray `.note-speaker-head` nodes
   (`notebook-html.ts:240-241`) and only reads `:scope > .note-line` children
   for body (`notebook-html.ts:229`).
4. `htmlToInlines` / caret helpers operate on `.note-line` only
   (`lineElFromSel` — `notebook-doc.tsx:20-26`).

The user cannot place a caret in the name or type into the header.

## 4. Enter / Backspace / double Enter to exit

### 4.1 Enter handling (custom — browser default prevented)

`onKeyDown` and `onBeforeInput` both intercept Enter / `insertParagraph` /
`insertLineBreak` (`notebook-doc.tsx:592-630`) and call `onEnter`
(`notebook-doc.tsx:507-536`).

```507:536:src/components/notebook-doc.tsx
  function onEnter() {
    if (enterLock.current) return;
    enterLock.current = true;
    window.setTimeout(() => {
      enterLock.current = false;
    }, 40);
    const line = lineElFromSel();
    if (!line) return;
    pushStruct();
    const empty = isLineHtmlEmpty(line);
    const kind = line.dataset.kind ?? "p";
    if (empty && (kind === "ul" || kind === "ol")) {
      line.dataset.kind = "p";
      line.classList.remove("note-line-h");
      parse();
      return;
    }
    const speaker = line.closest<HTMLElement>("[data-speaker-block]");
    const last = speaker?.querySelector<HTMLElement>(":scope > .note-line:last-of-type");
    if (empty && speaker && last === line) {
      const lines = speaker.querySelectorAll(":scope > .note-line");
      if (lines.length > 1) line.remove();
      const next = makeLine("p");
      speaker.after(next);
      placeCaret(next, true);
      parse();
      return;
    }
    splitLineAtCaret(line, kind);
  }
```

Behavior:

1. **Empty list line** → demote `ul`/`ol` to `p` (global, including inside
   speaker).
2. **Empty line that is the last child of a speaker section** → **exit
   section**:
   - If more than one child line exists, remove the empty trailing line.
   - Insert a new empty `p` **as a sibling after the `<section>`** (outside).
   - Place caret at start of that new line.
3. Otherwise → `splitLineAtCaret` (keep remaining text in a new line **still
   inside** the section if the current line is inside).

### 4.2 “Double Enter to exit”

There is **no** dedicated double-Enter counter. Exit is:

1. First Enter on a **non-empty** last line → splits / creates a new empty
   last child **inside** the section (`splitLineAtCaret`).
2. Second Enter on that **empty last** child → hits branch (2) above and
   leaves the section.

If the section already ends with an empty last line, a **single** Enter exits.

If the section has only one empty line and user presses Enter: that line is
**not** removed (`lines.length > 1` is false), a new line is still placed
**after** the section, and `htmlToBlocks` will keep/recreate a child for the
section (`children.length ? children : [emptyLine()]` —
`notebook-html.ts:235`). So exiting from a sole empty child leaves the
section with an empty body line in the model.

### 4.3 Backspace / Delete on empty line

Custom path only when the current line is HTML-empty
(`isLineHtmlEmpty` — `notebook-line.tsx:219-222`):

```608:647:src/components/notebook-doc.tsx
        const line = lineElFromSel();
        if ((event.key === "Backspace" || event.key === "Delete") && line && isLineHtmlEmpty(line)) {
          event.preventDefault();
          onMerge();
        }
      // …
        if (
          (inputType === "deleteContentBackward" || inputType === "deleteContentForward") &&
          line &&
          isLineHtmlEmpty(line)
        ) {
          event.preventDefault();
          onMerge();
        }
```

`onMerge` (`notebook-doc.tsx:538-548`):

- No-op if the document has ≤1 `.note-line` total.
- Removes the empty line from the DOM.
- Places caret after content of `previousLine` (document-order previous
  `.note-line`, which **may be outside** the speaker — `notebook-doc.tsx:739-745`).
- `parse()` rebuilds blocks.

Implications for speakers:

- Deleting the **last remaining** body line inside a section does **not** call
  `onRemoveSpeaker`. The `<section>` remains; `htmlToBlocks` synthesizes
  `children: [emptyLine()]` if zero lines remain (`notebook-html.ts:229-237`).
- Backspace on an empty first/only child may move caret to the previous
  document line (above the section) while leaving an empty section behind
  after re-parse — **exact caret/model interaction after rewrite is
  underspecified beyond the DOM remove + parse above.**

### 4.4 Backspace at start of a **non-empty** line

**Not customized** for speaker boundaries. Only empty-line merge and atomic
pill delete are intercepted. Browser contenteditable default applies for
merging text across nodes; **cannot be determined precisely from app code.**

## 5. Collapse / expand

Click handler on the doc (`notebook-doc.tsx:690-714`):

1. Ignore if click was on remove control.
2. If target is within `[data-toggle-speaker]` (the whole head):
   - Flip `section.dataset.collapsed` between `"true"` / `"false"`.
   - When collapsing, set `.note-speaker-preview` textContent to the first
     non-empty trimmed line `textContent` (ZWSP stripped).
   - `parse(false)` so `htmlToBlocks` persists `collapsed:
     node.dataset.collapsed === "true"` (`notebook-html.ts:236`).

CSS (`styles.css:434-461`):

- Collapsed: chevron rotates; **all** `:scope > .note-line` → `display: none`.
- Preview becomes `display: block`; name max-width 40%.

Collapsed body lines remain in the DOM and in the model; they are only hidden.

## 6. Deleting the block (×) — body text fate

### 6.1 Event path

`onPointerDownCapture` (`notebook-doc.tsx:677-688`) — capture phase so iOS text
node “×” still resolves via `parentElement` — calls
`onRemoveSpeaker(id)` with **`data-remove-speaker` = section block id**.

`onClick` also swallows the remove control to avoid toggle
(`notebook-doc.tsx:693-697`).

### 6.2 Model update — children discarded

```378:395:src/components/notebook-editor.tsx
  function removeSpeaker(id: string) {
    if (!id) return;
    const current = latest();
    const idx = current.blocks.findIndex((block) => block.id === id);
    if (idx < 0) return;
    const prev = idx > 0 ? current.blocks[idx - 1] : current.blocks[idx + 1];
    updateBlocks((blocks) => {
      const out = blocks.filter((block) => block.id !== id);
      return out.length ? out : [emptyLine()];
    });
    // … refocus prev …
  }
```

**Deleting the section deletes all child body lines with it.** There is no
flatten/promote of children into the parent document. Comment in editor:
immediate removal, no confirm ActionSheet (`notebook-editor.tsx:376-377`).

Focus after delete: previous block if any, else next; if that neighbor is a
speaker, focus its first child and set active speaker; else clear active.

## 7. Caret movement and selection around the block

### 7.1 What the app customizes

- Caret helpers: `placeCaret`, `placeAfterContent`, `placeLineOffset`,
  `lineCaretOffset` — all target `.note-line` contents.
- Selection of lines for heading/list toggles: `selectedLines` collects
  `.note-line` nodes intersecting the selection (`notebook-doc.tsx:28-37`).
- Undo snapshots store `lineId` + offset inside a line
  (`notebook-doc.tsx:411-415`).

### 7.2 What is **not** customized

- **No** ArrowUp/ArrowDown/Left/Right handlers around speaker heads.
- **No** logic preventing the caret from “landing” on the head (the head is
  `contenteditable=false`, so the browser skips it for typing; exact arrow
  behavior at the boundary is **browser-default / not determined in app
  code**).
- Multi-line selection that includes a speaker head: lines are still only
  `.note-line` nodes; the head is not a line. Whether the browser selection
  visually includes the head is unspecified in app code.

`previousLine` / document order treat all `.note-line` nodes flat — children
inside speakers participate in the same sequence as top-level lines
(`notebook-doc.tsx:739-745`, `flattenLines` at `729-737`).

## 8. Tapping above / below

**No dedicated hit-testing** for “tap gutter above section” or “tap below
header.” Pointer handling only:

1. Remove control (capture).
2. Toggle / collapse on head click.
3. Bible pill deep-link click.

Taps on empty padding / margins use normal contenteditable focus. The
guaranteed editable target **below** a trailing section is the extra
`emptyLine()` inserted when a section is last (`insertSpeakerSection`).
Tapping the non-editable head toggles collapse rather than placing a caret
in the first body line — **app code does not move caret into the first child
on head tap.**

## 9. Paste

`onPaste` on `NotebookDoc` (`notebook-doc.tsx:649-676`):

1. Parse clipboard for Bible passages via `parseClipboardPassages`
   (`notebook-html.ts:134-161`).
2. If **no** passages detected → **return without `preventDefault`** → browser
   default paste into the contenteditable (may insert arbitrary HTML inside
   the current line / section). **Speaker-specific cleanup of default paste is
   not implemented.**
3. If **one** passage → `insertHTML` of a ref pill at caret; `emit(true)`.
4. If **multiple** passages → create one new `.note-line` per passage and
   insert each with `after.after(node)` starting from the current line. If the
   caret line is inside a speaker, those new lines are DOM siblings under the
   **same** `<section>` (they stay inside the speaker). Empty original line is
   removed.

Ref pills themselves are `contenteditable="false"` spans
(`notebook-html.ts:34`).

## 10. Mapping to NoteDocumentV1 (serialization)

### 10.1 Web editor persist path (legacy)

While editing on web, `onBlocks` → `Note.blocks` with `type: "speaker"` and
`children: LineBlock[]` (`notebook.ts:19-26`). Collapsed flag optional.

Round-trip through DOM:

| Direction | Function |
| --- | --- |
| Model → HTML | `blocksToHtml` (`notebook-html.ts:180-208`) |
| HTML → Model | `htmlToBlocks` (`notebook-html.ts:224-244`) |

### 10.2 Native API mapping

`noteToDocument` / `blockToDoc` (`note-document.ts:434-446`):

| Legacy | NoteDocumentV1 |
| --- | --- |
| `type: "speaker"` | `type: "speakerSection"` |
| `children` | `blocks` (each line via `lineToDoc`) |
| `speakerId`, `title`, `id` | same fields |
| `collapsed: true` | `collapsed: true` (omitted when false) |
| `note.speakerId` | `noteSpeakerId` (whole-note chip — **not** a body block) |

`documentToNote` reverses with `docToBlock` (`note-document.ts:448-461`).

Line type map: `p/h/ul/ol` ↔ `paragraph/heading/bullet/numbered`
(`note-document.ts:128-143`). Inline `ref` ↔ `bibleRef`
(`note-document.ts` span converters).

### 10.3 HTML → V1 importer caveat

`htmlToDocumentBlocks` in `src/lib/native/api/html-to-document.ts` parses
generic `p/h/ul/ol/div` chunks and **does not** recognize
`note-speaker` / `data-speaker-block`. It is for coarse HTML imports, not a
lossless path for web editor speaker HTML. Lossless speaker structure goes
through legacy JSON or V1 JSON, not this HTML scraper.

### 10.4 Storage envelopes

See `docs/note-document-v1.md`: Postgres may hold V1 `{v:1,blocks}`, legacy
`Note.blocks` JSON, or rare HTML (backup column).

## 11. Bible ref pills vs speaker behavior

Pills are **orthogonal** to speaker sections but share the same line /
contenteditable machinery.

| Behavior | Location |
| --- | --- |
| Render as atomic `contenteditable=false` `.ref-pill` with ZWSP guards | `notebook-html.ts:34` |
| Two-step Backspace/Delete (arm → delete) | `handlePillDelete` `notebook-doc.tsx:319-360` |
| Click opens Bible deep link | `notebook-doc.tsx:716-723` |
| Empty-line checks treat a pill as non-empty | `isLineHtmlEmpty` `notebook-line.tsx:219-222` |
| Live inside speaker body lines like any other inline | no special-case exclusion |

Speaker **preview** text when collapsing uses `textContent` of lines (includes
pill labels as visible text in the preview string built at click time —
`notebook-doc.tsx:708-711`), while the initial `blocksToHtml` preview skips
ref inlines’ labels (only `part.type === "text"` —
`notebook-html.ts:196-203`). **Slight asymmetry** between initial HTML preview
and click-to-collapse preview for ref-only lines.

`@` / `/` triggers: `@` opens speakers; `/` opens verse picker
(`notebook-editor.tsx:664-674`). Both work inside speaker body lines because
parsing runs on the focused `.note-line`.
